# 补测批次作废记录：C4 b1/b2（生成脚本缺陷，非求解器失败）

**日期**：2026-10-15
**涉及**：`C4_4Vpp_D50_5ms_b1`、`C4_4Vpp_D50_5ms_b2`
**处置**：两次运行整体作废，原件移入 `_void_launch_artifacts_c4_b1b2\`，**不计入尝试预算**，也不得作为求解器不稳定的证据引用。

## 发生了什么

批次 1 的第一次尝试（`C4_4Vpp_D50_5ms_b1`）以"Owned Multisim process exited"告终、raw 为 0 字节；第二次（`_b2`）报 `Error: Internal simulation error.`。表面上像是又一轮环境不稳定，但日志里有一条与运行目录不符的路径：

```
write-and-destroy-iplot "D:/ms_xsp/stage3_acceptance/s0304_final2_20261014/C4_4Vpp_D50_5ms_b2.raw"
```

检查后确认这是我的 `生成补测用例.ps1` 的两个缺陷，与求解器行为无关：

1. **`source` 行没有改写**。生成脚本只对输出路径做了字符串替换，`source` 行原样从被复制的 `.cmd` 带过来。对 C4 基准而言，源文件是
   `D:\...\副本专用文件夹\final2_20261014\REF_4Vpp_tail.cmd`，其 `source` 指向
   `.../s0304_final2_20261014/REF_4Vpp_tail.cir`——**该目录真实存在同名网表**，所以引擎不会报错，而是安静地去仿真另一个目录里的网表。
2. **输出路径也被写进了该目录**（同一行缺陷的另一半）。

因此这两次尝试**跑的不是本批次登记的用例**，其失败不能归因于环境，也不能记作 C4 基准的失败。

## 同一个缺陷的另一半：其余 18 个 `.cmd`

全目录审计（逐文件核对 `source` 与 `write-and-destroy-iplot` 是否指向自身 tag）发现：

| 文件 | 问题 | 后果 |
|---|---|---|
| `C4_4Vpp_D50_5ms_b1/b2.bak`（已作废） | `source` 指向 `s0304_final2_20261014` | 仿真了错误目录的网表 |
| `C4_4Vpp_D50_7ms_b1/b2/b3` | 同上 | 未运行，已重新生成 |
| `C1/C2/C3/C6/C7_*_b*.cmd`（15 个） | `source` 指向**原始**网表而非本 tag 的副本 | 数值会相同（两者 SHA-256 一致），但**追溯链错误** |

第二类不影响数值（副本与原始网表逐字节相同，已验证 SHA-256），但会让"该次尝试用的是哪个网表"这一条无法自证，故一并重新生成。

## 修复与复核

`生成补测用例.ps1` 改为**显式重建**两条路径行（而非子串替换），并在生成后强制断言：

- `source` 必须等于本 tag 的 `.cir` 绝对路径；
- `write-and-destroy-iplot` 必须等于本 tag 的 `.raw` 绝对路径；
- 命令文件中**不得**再出现 `s0304_final2_20261014`；
- 命令文件中不得残留源 tag 的 `.raw` 名；
- `tran` 行必须与登记条件一致。

生成后独立复审 20 个文件：全部通过（source/raw 均指向自身 tag）。同时 `.cir` 副本改为幂等（哈希一致则跳过，不一致则拒绝覆盖）。

## `run_budget.ps1` 的配套修正

原驱动的 `run_one.ps1` 路径写成运行目录，实际 runner 位于工作区，导致**前两次调用根本没有启动仿真**（`-File` 参数不存在，退出码 −196608）。已验证该情形**不产生 status 文件**，故驱动现在以"是否存在 status 文件"区分"真的跑了并失败"与"根本没启动"：后者记为 `LAUNCH_FAILED` 且**不消耗尝试预算**。上述 C4 b1/b2 是真正启动过的尝试，但其用例作废，故这两次同样不计入预算。

## 保留边界

1. 本记录所涉两次运行**不是**求解器或环境失败的证据。
2. C4 基准的预算是 2 次，**从修复后的下一次尝试起算**。
3. 作废原件保留在 `_void_launch_artifacts_c4_b1b2\`，仅用于追溯这次缺陷，**不得引用其数值**。
