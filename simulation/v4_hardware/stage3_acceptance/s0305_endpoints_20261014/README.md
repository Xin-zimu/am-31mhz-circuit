## 环境不稳定的已知事实

2026-10-14 23:30 重启后，**同一 C2 网表**（傍晚成功过）重跑失败，而**同一 20 μs 短窗**两次都成功；已验收标称网表本身也会失败。故失败与输入工况**无关**，是概率性的。全窗形式下 16 次尝试成功 4 次（C7 连续 8 次失败后第 9 次成功）。**长窗用例必须设重试预算并逐次登记尝试**；单次失败不构成工况判定。

## 配置（原计划条件）

- 初值：UIC，C111=0.43 V、C115=−4.1 V、CBB=4.5 V，属于预充电测试。
- 初始统一计算：`tran 2n 5m 4.5m 2n uic`；从 0 积分，仅保存 4.5～5 ms。
- 完整网表中的 LM393、OPA197、射频及检波链路均保留。接收增益、负载、频率电阻均不变。
- C1=1 Vpp/10%；C2=1 Vpp/50%；C3=4 Vpp/10%；C6=4 Vpp/30%；C7=3 Vpp/50%。变动值来自既有 `potentiometer_settings.csv`。
- 已为 4 Vpp 或 50% 的控制量继续使用标称网表原值，避免引入无关舍入差异。
- `.cmd` 保留历史 `set` 行以维持与 C4/C5 相同调用；这些行不证明容差实际生效。有效容差依据 S03-04 诊断为引擎默认 RELTOL=1e-3、TRTOL=7。日志报告 TMAX 从 2 ns 自动调整至约 1.00806 ns，实际时间轴另验。本轮已验证：**把容差写进网表 `.OPTIONS` 也不能改变失败结局**。
- 证据入口是 COM `DoCommandLine` 的 `source`+`tran` 引擎。没有新增原生 GUI 点击运行的声明。


## 运行

1. 用 Python 执行 `prepare_cases.py` 生成输入副本、ASCII 运行目录及配置清单。已有不同内容文件会拒绝覆盖。
2. 确认没有其他 Multisim 实例。`run_one.ps1` 会拒绝在已有实例时运行；结束时只关闭本次创建的进程。
3. 用 PowerShell 执行 `run_all.ps1`。它串行调用 32 位 Windows PowerShell；单例失败即停止。每次仿真超时 1800 秒，遇已存在的日志、状态或原始结果会拒绝覆盖。
4. 首次 C1 运行发生进程崩溃，原始失败状态与 Windows 事件保留。标称与 C1 的 20 μs 诊断成功后，用同一网表、同一积分配置及新标签 `C1_1Vpp_D10_5ms_retry1` 重跑；`selected_runs.json` 指定汇总采用的尝试。
5. 按需使用 `run_all.ps1 -Tags @('标签1','标签2')` 指定队列；不覆盖既有结果。运行目录固定为 `D:\ms_xsp\stage3_acceptance\s0305_endpoints_20261014`，以避开求解器的中文路径兼容问题。

## 测量和核验

运行 `analyze_cases.py`，仅处理状态为 `COMPLETED` 的预充电用例及既有 C4/C5。可在队列运行期间执行。脚本会核对原始点数、时间终点、有限值与单调时间轴，并把新原始数据复制到本目录。

冷启动全窗四组用 `analyze_fullwindow.py`（独立实现，取窗 1.5～2 ms，`tran` 与初值不同，不覆盖预充电结果）。判定表由 `build_verdict.py` 生成 `verdict_table.json`；`print_verdict_inputs.py` 只读打印判定输入。

测量沿用 `measure_stage3.py` 的交点函数与第 6.2 节口径：2 ns 均匀插值、P98−P2、梯形积分时间加权均值、末尾五完整输入周期；输出频率/占空比单独使用输出自身门限与完整输出周期。原始极值来自原始自适应数据，同时保留多交越计数。报告末五周期筛查和整个保存尾段的漂移趋势，不把 0.1% 筛查称为评分标准或全时间稳定性证明。

`verify_evidence.py` 核对原基线清单的 SHA-256、五组网表仅改变指定输入电阻、源/运行目录内容一致、已有 C4/C5 数字复现、新原始波形及归档副本一致。它在数据未齐时如实记录 `all_seven_available=false`。

主要产物：`summary.json`、`fullwindow_summary.json`、`verdict_table.json`、各组 `C*_metrics.json` / `C*_cycles.json`、`S03_05_waveforms_and_drift.png`、`evidence_audit.json`。大型 `.raw` / `.npz` 遵循仓库现有忽略规则，由哈希台账追踪；它们仍保存在本地，不因不入 Git 而删除。

## 结论边界

此处检查代表性离散点，不等于 S06 全范围/容差扫描。C1/C3/C6/C7 的数据为冷启动全窗条件，与 C2/C4/C5 的预充电条件不同，**幅度与均值不可直接互比**。C2 未通过其自身重复性筛查（0.2566%），只能表述为"完成且无引擎错误"。每个端点仅 1 次成功数据（n=1）。引擎失败已定性为概率性且与工况无关，但未定位根因。S03-04 的冷启动验收继续连同其第 6.3 节七条边界引用。当前理想载波、通道、电源仍不证明实际 31 MHz 振荡器、无线距离、功耗或实物性能。
