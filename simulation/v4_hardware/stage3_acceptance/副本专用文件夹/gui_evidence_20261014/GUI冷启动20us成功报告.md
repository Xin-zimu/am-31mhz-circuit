# 原生 GUI 冷启动 20 µs 复现成功报告

日期：2026-10-14。目录：`simulation/v4_hardware/stage3_acceptance/副本专用文件夹/gui_evidence_20261014/`。

**结论：把 RELTOL 由 1e-4 改为 1e-3、TRTOL 由 1 改为 7 后，原生 GUI 在 TSTEP=TMAX=1 ns 下跑满了 20 µs，四条曲线各 20,038 点。此前"GUI 在 225.797635 ns 不收敛"的限制解除，且**两次运行只改了这两个选项**，构成单变量对照。**

## 2. 机制得到独立验证

上一轮只读诊断的结论是：**GUI 分析入口的容差比命令行引擎紧约 3.3 倍**，因此在 225.806 ns（7 个载波周期）那个真实收敛危机处没有余量。本次实测把这条因果链补完：

| 步进指标 | GUI 1e-4（失败） | GUI 1e-3（成功） | 命令行引擎 |
|---|---:|---:|---:|
| 中位步长 | 307.037 ps | **1000.000 ps** | 1008.065 ps |
| 达到上限比例 | 11.74% | **99.75%** | 91.71% |
| **事件处最深步长** | **0.0116 ps** | **31.2500 ps** | 1.2095 ps |

三处关键吻合：

1. **改成 1e-3 后，GUI 的中位步长变成 1000 ps，与引擎的 1008 ps 基本一致** —— 说明容差就是造成 3.3 倍差距的原因。
2. **在 225.806 ns 处，GUI 只需降到 31.25 ps 就能通过**（失败时被压到 0.0116 ps）—— 同一个事件，不同的余量。
3. 事件前后步长行为：`193.55–225.81 ns` 最小 31.25 ps，`225.81–258.06 ns` 最小 69.97 ps，此后**稳定在 1000 ps 上限，直到 20 µs 结束**。

## 5. 一个应当记录的教训

1e-3 是 SPICE 默认值，也是本项目**标称 5 ms 与冷启动 7 ms 实际使用的值**。1e-4 是 Multisim 分析对话框里的一个更严设置，它让 GUI 成了与所有既有验收数据不一致的异类通道。

因此这次调整**不是"放宽标准凑结果"**，而是消除人为不一致。若要保留 1e-4 的严格性，则应对全部历史运行重跑并重新验收 —— 本次未做，也不建议在 S03 收尾阶段做。
