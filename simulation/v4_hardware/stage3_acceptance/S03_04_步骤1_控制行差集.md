## 2. 分析控制行差集

GUI 导出网表**不含任何** `.tran` / `.options` / `.ic` / `.nodeset` 行（实测 0 条）。控制行完全由工程文件内的分析块给出。逐项对照：

| 控制项 | GUI 冷启动工程（失败） | 引擎成功运行 | 是否差异 |
|---|---|---|---|
| TSTEP | 2 ns | 2 ns（命令） | 否 |
| TSTOP | 20 µs | 20 µs | 否 |
| TSTART | 0 | 0 | 否 |
| TMAX（请求） | 2 ns | 2 ns | 否 |
| TMAX（实际生效） | **1.00806 ns**（自动调整） | **1.00806 ns**（自动调整） | **否** |
| IC | uic | uic（命令） | 否 |
| RELTOL | 1e-4（启用） | 引擎 `set reltol=1e-4` | 否 |
| TRTOL | 1（启用） | 引擎 `set trtol=1` | 否 |
| ITL4 | 100 / 500（按试验） | 100 / 500 | 否 |
| METHOD | trapezoidal（TRAP500 试验）/ gear | gear | 部分 |
| MAXORD | 默认 | 默认 | 否 |
| RSHUNT | 1e12（启用） | 1e12 | 否 |
| CONVLIMIT / DYNAMICDC / INERTIALDELAY / SUPOSC | 全部启用 | 全部启用 | 否 |

GUI 冷启动工程启用项（自 `gear500_uic_settings.xml`、`decoded_TMAX1ns.xml` 逐项读出）：
`reltol=0.0001`、`trtol=1`、`itl4=500`、`method=gear`、`convlimit`、`rshunt=1e+12`、`dynamicdc`、`inertialdelay`、`suposc`、`rawfileformat=Binary`；未启用项保持 XSPICE 默认。

**门禁结论：控制行差集为空。GUI 与引擎在时间步控制上逐项一致，不存在“引擎有 GUI 没有的隐藏设置”。**

## 3. 由差集直接排除的假设

- 电路元件内容不是原因（第 1 节）。
- 分析控制行（`.tran`/`.options`/`.ic`/`.nodeset`）不是原因（第 2 节）。
- 因此步骤 3、步骤 4 的前提（“GUI 默认值被污染”或“引擎另有一套隐藏默认值”）**不成立**：两边已逐项相同，没有可移植的差异项。

## 4. 关键负面发现：引擎的 `set` 与 `options` 对求解器无效

同一网表单变量对照（`A_ref` vs `B_xspice_default`，两个 .raw 的数值数组逐位相同）：

- `set trtol/reltol/itl4/method` 任意组合、任意写法（含帮助文档的 `set reltol=0.01` 无空格形式）、放在 `source` 之前或之后 → 输出**逐位相同**；
- `option` 命令直接报 `option: no such command available in XSPICE`；
- 在仅由 LTE 决定步长的 RC/SIN 电路中，RELTOL 从 1e-9 到 0.1、TRTOL 从 0.01 到 20 均**不改变时间轴**；
- 唯一真正改变求解的是 `rshunt`（改变数值，因为它是并联电导）。

**后果：此前“引擎用了另一套 reltol/trtol”的说法缺乏依据。历史上“引擎 5 ms 与 GUI 2 ms 数值不同”不能归因于求解选项差异。**

## 5. 步骤 1 真正定位到的差异：初始自适应步长差 10 倍

在**完全相同的控制行**下，两条轨迹从第一个自适应步长起就分叉：

| 步序 | GUI 冷启动 dt | 引擎 dt | 比值 |
|---:|---:|---:|---|
| 0 | 2.000e-11 | 2.000e-11 | 1 |
| 1 | 8.000e-15 | 8.000e-14 | 10 |
| 2 | 1.600e-14 | 1.600e-13 | 10 |
| 3 | 3.200e-14 | 3.200e-13 | 10 |
| 4 | 6.400e-14 | 6.400e-13 | 10 |
| 5 | 1.280e-13 | 1.280e-12 | 10 |

引擎在每个时间点都尝试更大的步长；GUI 的初始步长被压小 10 倍并持续更保守。这是**时间步控制策略**差异，不是容差数值差异；在全部控制项都相同时它属于**求解器实现/调用方式**层面，而非工程设置层面。
