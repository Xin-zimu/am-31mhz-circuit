### 3.1 52.3% 的错误已精确复现

```
错误加法 = 10（取样）+ 15.924（线圈）+ 0.898（微调）+ 3.6153（天线支路，未做 k² 折算）
         = 30.4371 Ω   ← README 引用的「30.44 Ω」
正确端口电阻 = 30.0321 Ω
```

用错误加法得到的三个比例与 README 逐位吻合：线圈 52.32%（写成 52.3%）、取样 32.85%（32.9%）、辐射 2.42%（2.4%）。**证明这是「分子分母不同电流基准」，不是四舍五入。**

| 天线欧姆（含接触） | 0.04453 | 8.2% |

**加载线圈是最大单项损耗的判断仍成立**，依据是 53.0%（端口基准）/ 53.4%（功率基准）。

## 8. 教训（避免重蹈）

1. **不要反复轮询后台仿真。** 本次浪费大量轮次盯 `job_output`。启动后台任务后应去做别的事。
2. **单位换算是本阶段最大的坑。** 报告用 pF、engine 用 F，任何重复换算都会静默产生「看起来合理」的错误（Prad=1e-24 而不报错）。新代码必须走 `reanalyse.job_from_metrics()`。
3. **`force=True` 会先删 raw 再跑。** 中途 kill 就丢数据。本次因此丢了 3 个 raw。
4. **不要并行跑同一批 case 名两次。** 本次因重复启动导致 12 个 ngspice 抢 6 个 raw，整批作废。
5. **角点必须区分「重调」与「未重调」。** 不区分的话寄生与容差角点会被调谐电容吸收，测不出任何东西。
